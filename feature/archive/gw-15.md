# GW-15: Require explicit capability input limits

## Problem

Missing manifest input limits silently use built-in defaults, hiding configuration omissions.

## Impact

- Operators cannot tell whether capability limits were explicitly chosen.
- Existing manifests must add max_input_chars to every ranked capability binding.

## Shorthand solution

Remove DefaultMaxInputChars. Require an integer max_input_chars from 200 through 500000 on every ranked binding. Missing values fail with "capability <id> has not defined max_input_chars please see documentation". Reject invalid limits during validation and do not default them during resolution. Advertise required limits and their bounds in management discovery; update the sample manifest and documentation.
