# GW-13: Low-priority terminal live debug session

## Problem

Operators need a terminal request that exercises the Redis processing flow and returns a result or a visible error.

## Impact

- Manual requests should use LOW priority alongside regular traffic.
- Quoted prompts must remain valid JSON, and failed requests must be detectable by shell callers.

## Shorthand solution

Extend the existing HTTP smoke-test helper with explicit LOW priority, safe JSON encoding, bounded connection/response waits, and HTTP error exit codes with response bodies. Default to intent-classification and document a live session with gateway logs. Redis is assumed to be running; the gateway and its configured model must also be available.
